# آپلودساز شخصی

یک سایت آپلودساز تک‌کاربره با Node.js (Express) برای cPanel.

## راه‌اندازی روی cPanel

1. محتوای این پوشه را (بدون `node_modules`) در یک پوشه روی هاست آپلود کنید، مثلاً `~/uploader`
   (**خارج از `public_html`** تا فایل‌های `data` مستقیم در دسترس نباشند).
2. cPanel ← **Setup Node.js App** ← **Create Application**
   - Node.js version: ۱۸ یا بالاتر
   - Application mode: Production
   - Application root: `uploader`
   - Application URL: دامنه یا ساب‌دامین دلخواه
   - Application startup file: `server.js`
3. در همان صفحه بخش **Environment variables** این متغیرها را اضافه کنید:

   | نام | توضیح |
   |---|---|
   | `ADMIN_USER` | نام کاربری ورود (الزامی) |
   | `ADMIN_PASS` | رمز ورود (الزامی، قوی انتخاب کنید) |
   | `SESSION_SECRET` | یک رشته تصادفی بلند (پیشنهادی) |
   | `QUOTA_GB` | سقف مصرف دیسک به گیگابایت؛ پیش‌فرض ۴.۵ |
   | `DATA_DIR` | مسیر ذخیره فایل‌ها؛ پیش‌فرض `./data` |
   | `TRUST_PROXY` | تعداد پروکسی‌های معتبر پشت سرور برای تشخیص IP کلاینت؛ پیش‌فرض `1` (`0` = بدون پروکسی) |

4. روی **Run NPM Install** بزنید، سپس **Restart**.
5. آدرس سایت را باز کنید و با `ADMIN_USER` / `ADMIN_PASS` وارد شوید.

> برای تست روی کامپیوتر خودتان می‌توانید فایل `.env.example` را به `.env` تغییر نام دهید و `npm install && npm start` بزنید. برای اجرای تست خودکار: `npm test` (تست مرورگری `viewer` فقط وقتی اجرا می‌شود که `npm i --no-save jsdom` زده باشید).

## نکات مهم

- **آپلود بدون محدودیت حجم**: فایل در تکه‌های ۵ مگابایتی آپلود می‌شود، پس محدودیت زمان/حجم درخواست پروکسی هاست مشکل ایجاد نمی‌کند. اگر ارتباط قطع شود هر تکه تا ۵ بار دوباره ارسال می‌شود. تنها سقف واقعی، فضای دیسک است (`QUOTA_GB`).
- **ZIP**: فایل بعد از آپلود فشرده می‌شود و فایل اصلی حذف می‌شود. موقع فشرده‌سازی موقتاً به فضای حدود دو برابر حجم فایل نیاز است.
- **رمز فایل**: دانلودکننده باید قبل از دریافت فایل رمز را وارد کند (رمز به‌صورت hash ذخیره می‌شود). فایل ZIP خودش رمزگذاری نمی‌شود.
- **انقضا**: بعد از رسیدن زمان انقضا، فایل **به‌طور کامل از سرور حذف می‌شود** (بررسی هر یک دقیقه).
- **باطل کردن لینک**: لینک فوراً از کار می‌افتد ولی فایل می‌ماند؛ هر وقت خواستید «ساخت لینک جدید» بزنید. برای حذف کامل از «حذف» استفاده کنید.
- بعد از ۵ بار رمز اشتباه (ورود ادمین یا رمز فایل)، ۱۵ دقیقه محدودیت اعمال می‌شود.
- حتماً دامنه را با **HTTPS** استفاده کنید (AutoSSL در cPanel).
- هدرهای امنیتی (CSP، HSTS روی HTTPS، `no-store` برای API) به‌صورت پیش‌فرض فعال هستند.
- فایل‌های ناتمام، رکوردهای ناموفق (بعد از ۲۴ ساعت) و فایل‌های یتیم روی دیسک به‌صورت خودکار پاک می‌شوند.
- هیچ‌وقت `data/`، `.env` و فایل‌های لاگ را در گیت قرار ندهید (در `.gitignore` هستند).
- از پوشه `DATA_DIR` (به‌خصوص `db.json`) بکاپ بگیرید؛ اطلاعات لینک‌ها آنجاست.

## QR کد

کنار لینک هر فایل و هر متن دکمهٔ **QR** هست: QR کد را نشان می‌دهد و با «دانلود تصویر» به‌صورت PNG (۱۰۲۴ پیکسل، با حاشیهٔ استاندارد) ذخیره می‌شود. QR کاملاً داخل مرورگر ساخته می‌شود (کتابخانهٔ محلی `qrcode-generator`)؛ هیچ لینکی به سرویس خارجی فرستاده نمی‌شود. برای لینک‌های E2E، QR شامل کلید (`#k=…`) هم هست.

## چند فایل در یک لینک

اگر چند فایل را انتخاب کنید، گزینهٔ «یک لینک برای همه فایل‌ها» ظاهر می‌شود (پیش‌فرض روشن). فایل‌ها یکی‌یکی آپلود می‌شوند و سرور همه را در **یک ZIP** (با امکان رمز AES-256 برای خود ZIP) قرار می‌دهد و فقط یک لینک و یک QR می‌سازد. نام فایل‌های تکراری خودکار `نام (2).ext` می‌شوند و حداکثر ۲۰۰ فایل در هر لینک مجاز است. اگر خاموشش کنید، برای هر فایل یک لینک جدا ساخته می‌شود.

## رمزگذاری سرتاسری (E2E)

با روشن کردن «رمزگذاری سرتاسری» در پنل فایل یا متن، **رمزگذاری داخل مرورگر شما** انجام می‌شود و سرور فقط داده‌های رمزشده را می‌بیند (حتی نام فایل رمز می‌شود).

- الگوریتم: AES-256-GCM با WebCrypto. فایل‌ها در بلوک‌های ۱ مگابایتی رمز می‌شوند و شمارندهٔ بلوک و پرچم «بلوک آخر» جزو داده‌های احراز هویت هستند، پس **دست‌کاری، حذف انتهای فایل و جابه‌جایی بلوک‌ها** هنگام رمزگشایی تشخیص داده می‌شود.
- کلید: بدون رمز، یک کلید تصادفی ۲۵۶ بیتی در بخش `#k=…` لینک قرار می‌گیرد. مرورگر این بخش را هرگز به سرور نمی‌فرستد (در لاگ‌ها هم نمی‌آید). با رمز، کلید از رمز با PBKDF2-SHA256 (۶۰۰٬۰۰۰ تکرار) ساخته می‌شود و لینک بدون کلید کار می‌کند؛ رمز را از مسیری جدا بفرستید.
- گیرنده باید لینک را **کامل** باز کند. رمزگشایی با `/viewer.js` در مرورگر او انجام می‌شود. در Chrome/Edge فایل مستقیم روی دیسک نوشته می‌شود و محدودیت RAM ندارد؛ در مرورگرهای دیگر کل فایل در حافظه جمع می‌شود (برای فایل‌های چندگیگابایتی مناسب نیست).
- کلید لینک‌های ساخته‌شده فقط در `localStorage` **همین مرورگر** نگه داشته می‌شود تا بتوانید لینک کامل را دوباره کپی کنید. اگر داده‌های مرورگر پاک شود یا از دستگاه دیگری وارد شوید، لینک بدون رمز دیگر قابل بازسازی نیست (برچسب «کلید روی این دستگاه نیست» نشان داده می‌شود). لینک‌های با رمز هیچ‌وقت به کلید ذخیره‌شده نیاز ندارند.
- متن‌های E2E یک‌بار مصرف: کلید/رمز قبل از درخواست از سرور در مرورگر بررسی می‌شود؛ پس رمز اشتباه یا لینک ناقص متن را نمی‌سوزاند.
- در حالت E2E این قابلیت‌ها غیرفعال است چون سرور محتوا را نمی‌بیند: ZIP، تغییر نام، آپلود گروهی و رمز سمت سرور.
- **محدودیت‌ها (مهم):** (۱) فقط روی HTTPS یا localhost کار می‌کند (WebCrypto). (۲) جاوااسکریپت رمزگشا را همین سرور می‌دهد؛ اگر خود سرور به‌طور فعال هک شود، مهاجم می‌تواند اسکریپت را عوض کند. E2E در برابر خواندن دیسک/بکاپ/میزبان محافظت می‌کند، نه سروری که کاملاً در اختیار مهاجم است. (۳) رمز ضعیف قابل حدس‌زدن آفلاین است (توکن لینک را داشته باشند)؛ رمز قوی بگذارید («تولید رمز» را بزنید). (۴) عنوان متن و اندازه و زمان‌ها رمز نمی‌شوند.

## ارسال متن امن

برای ارسال متن‌های طولانی (رمز، کلید، یادداشت) از پنل «ارسال متن امن» استفاده کنید؛ تا ۱ مگابایت.

- متن با **AES-256-GCM** رمزگذاری و فقط به‌صورت رمزشده روی دیسک ذخیره می‌شود (در `db.json` هیچ متن خامی نیست).
- اگر **رمز** بگذارید، کلید رمزگذاری با `scrypt` از همان رمز ساخته می‌شود؛ یعنی بدون رمز، حتی با دسترسی به سرور و فایل‌ها نمی‌توان متن را خواند. رمز ذخیره نمی‌شود، پس **قابل بازیابی نیست**. رمز را از راهی جدا از لینک بفرستید.
- بدون رمز، متن با کلیدی مشتق از `SESSION_SECRET` رمزگذاری می‌شود (محافظت در حالت ذخیره).
- گزینهٔ **یک‌بار مصرف**: بعد از اولین نمایش، متن برای همیشه حذف می‌شود. باز کردن لینک فقط صفحهٔ «نمایش متن» را نشان می‌دهد (پیش‌نمایش‌گرهای پیام‌رسان‌ها متن را نمی‌خوانند و آن را نمی‌سوزانند).
- انقضا، باطل کردن لینک و محدودیت ۵ تلاش اشتباه (۱۵ دقیقه قفل) مثل فایل‌ها کار می‌کند. عنوان متن رمزگذاری نمی‌شود.
- متن در صفحهٔ نمایش به‌صورت امن escape می‌شود و کش نمی‌شود.

## مسیرها

- `/` پنل مدیریت (نیازمند ورود)
- `/d/<token>` صفحه دانلود عمومی (بدون ورود)
- `/d/<token>/file` دانلود مستقیم (از resume هم پشتیبانی می‌کند)
- `/t/<token>` صفحهٔ عمومی نمایش متن امن
- `/e2e.js`، `/viewer.js` اسکریپت‌های رمزگذاری/رمزگشایی سمت مرورگر؛ `/vendor/qrcode.js` کتابخانهٔ QR

## طراحی و فونت

- ظاهر پنل و صفحهٔ دانلود بر پایهٔ دیزاین سیستم [beUI](https://github.com/starc007/ui-components) است (توکن‌های رنگ، شعاع‌ها، انیمیشن‌ها). چون این پروژه بدون مرحلهٔ build اجرا می‌شود، کامپوننت‌های ری‌اکت کپی نشده‌اند و همان زبان طراحی با HTML/CSS ساده پیاده شده است.
- فونت **وزیر (Vazirmatn)** به‌صورت محلی در `public/fonts/` قرار دارد (لایسنس OFL در همان پوشه). هیچ درخواستی به سرویس خارجی ارسال نمی‌شود.
- پنل و صفحهٔ دانلود ریسپانسیو هستند و تم روشن/تیره دارند (پیش‌فرض: تنظیم سیستم؛ دکمهٔ تغییر تم در هدر پنل).
- پوشهٔ `public/fonts` باید همراه پروژه آپلود شود، چون صفحهٔ دانلود عمومی هم فونت را از `/fonts/` می‌گیرد.

## عیب‌یابی

- خطای `Cannot find module 'archiver-zip-encrypted'` (یا هر ماژول دیگر) در لاگ یعنی وابستگی‌ها نصب نشده‌اند: در cPanel روی **Run NPM Install** بزنید و بعد **Restart** کنید.
- اگر بعد از ورود، کوکی ذخیره نمی‌شود، مطمئن شوید سایت با HTTPS باز شده و `TRUST_PROXY` درست تنظیم است.
